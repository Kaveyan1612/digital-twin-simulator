# Machine Learning Documentation

## Overview

The Digital Twin Simulator includes two ML components:

1. **Anomaly Detection** - Isolation Forest for detecting anomalous operating conditions
2. **Predictive Analytics** - Random Forest regression for forecasting sensor values

Both models are trained on data generated by the physics-based simulator, ensuring realistic training distributions.

## Anomaly Detection

### Algorithm: Isolation Forest

Isolation Forest is an unsupervised anomaly detection algorithm that isolates anomalies by randomly selecting features and splitting values.

**Why Isolation Forest?**
- Works well with high-dimensional data
- No need for labeled anomaly data
- Fast training and inference
- Handles multi-variate anomalies naturally
- Robust to outliers in training data

### Features (15 dimensions)

| Feature | Description | Normalization |
|---------|-------------|---------------|
| speed_norm | Current speed / 5000 | [0, 1] |
| target_speed_norm | Target speed / 5000 | [0, 1] |
| load_norm | Load / 100 | [0, 1] |
| torque_norm | Torque / 100 | [0, 1] |
| voltage_norm | Voltage / 500 | [0, 1] |
| current_norm | Current / 50 | [0, 1] |
| power_norm | Power / 20 | [0, 1] |
| temperature_norm | Temperature / 150 | [0, 1] |
| vibration_norm | Vibration / 10 | [0, 1] |
| efficiency | Efficiency (already 0-1) | [0, 1] |
| health_score_norm | Health / 100 | [0, 1] |
| running | 1 if running, 0 if stopped | {0, 1} |
| speed_deviation_norm | |target-speed| / 5000 | [0, 1] |
| temp_current_interaction | temp × current / (150×50) | [0, 1] |
| vib_load_interaction | vib × load / (10×100) | [0, 1] |

### Training Data Generation

Training data is generated by running the simulator under various conditions:

```python
# Normal operation scenarios
- Steady state at various speeds (1000-5000 RPM)
- Various loads (0-100%)
- Different voltage levels
- Transient conditions (acceleration/deceleration)

# Anomalous conditions (for validation)
- Overtemperature (fault injection)
- Overcurrent (fault injection)
- High vibration (fault injection)
- Overspeed (fault injection)
```

### Model Configuration

```python
IsolationForest(
    contamination=0.05,      # Expected anomaly ratio
    n_estimators=100,        # Number of trees
    max_samples='auto',      # Sample size per tree
    random_state=42,         # Reproducibility
    n_jobs=-1                # Parallel training
)
```

### Training Process

1. Generate 10,000+ normal operating samples
2. Extract features using `extract_features()`
3. Fit StandardScaler on features
4. Train Isolation Forest on normalized features
5. Save model and scaler with joblib

### Inference

```python
# For each new state
features = extract_features(state).reshape(1, -1)
features = scaler.transform(features)
score = model.score_samples(features)[0]      # Anomaly score
prediction = model.predict(features)[0]        # -1 = anomaly, 1 = normal
confidence = min(1.0, max(0.0, (0.5 - score) * 2))
```

### Integration with Rule Engine

The ML detector runs **alongside** (not replacing) the rule engine:

```
State → Rule Engine → Anomalies
     → ML Detector → Anomalies
     → Combine → Final anomalies (highest severity)
```

**Important**: Safety-critical rules (temperature > 110°C) always trigger regardless of ML output.

## Predictive Analytics

### Algorithm: Random Forest Regression

Ensemble of decision trees for multi-output regression.

**Why Random Forest?**
- Handles non-linear relationships
- Robust to outliers
- Provides feature importance
- Fast inference
- No extensive hyperparameter tuning needed

### Prediction Targets

| Target | Horizon | Model Type |
|--------|---------|------------|
| Temperature | 60s | Random Forest |
| Vibration | 60s | Random Forest |
| Speed | 60s | Random Forest |
| Health Score | 60s | Random Forest |

### Features (13 dimensions)

Same as anomaly detection minus interaction terms.

### Training Data

Requires sequential data with time offsets:

```python
# For each sample at time t
X = features_at_t
y_temp = temperature_at_t+10s
y_vib = vibration_at_t+10s
y_speed = speed_at_t+10s
y_health = health_at_t+10s
```

### Simple Predictor (Fallback)

Linear trend extrapolation when ML model unavailable:

```python
# Temperature
recent = history[-10:]
trend = polyfit(recent, deg=1)[0]
predictions = [last + trend * dt for dt in horizons]
```

### Model Configuration

```python
RandomForestRegressor(
    n_estimators=50,
    max_depth=10,
    random_state=42,
    n_jobs=-1
)
```

### Evaluation Metrics

| Target | MAE | RMSE | R² |
|--------|-----|------|-----|
| Temperature | < 2.0°C | < 3.0°C | > 0.85 |
| Vibration | < 0.5 mm/s | < 0.8 mm/s | > 0.80 |
| Speed | < 50 RPM | < 80 RPM | > 0.90 |
| Health | < 5% | < 8% | > 0.85 |

### Predictive Warnings

System generates warnings when predictions exceed thresholds:

```python
# Temperature warning
if any(p.value > 90 for p in temp_predictions):
    warning = PredictiveWarning(
        type="PREDICTIVE_OVERTEMPERATURE",
        message=f"Temperature predicted to reach {max_temp}°C in {time}s",
        severity="HIGH" if max_temp > 110 else "MEDIUM"
    )
```

## Deployment Considerations

### Model Serving

- Models loaded at startup (~50MB total)
- Inference < 5ms per sample
- No GPU required
- Thread-safe (sklearn models)

### Monitoring

Track in production:
- Prediction latency
- Anomaly rate (should be ~5%)
- Warning accuracy
- Model drift detection

### Retraining Schedule

- **Anomaly**: Monthly or after significant process changes
- **Prediction**: Weekly (more sensitive to drift)
- **Automated**: CI/CD pipeline with validation gates

## Limitations & Future Work

### Current Limitations

1. **No online learning** - Models static after deployment
2. **Single motor** - No multi-motor correlation
3. **Fixed horizon** - 60s prediction window
4. **No uncertainty quantification** - Point predictions only

### Planned Improvements

1. **LSTM/GRU** for temporal sequences
2. **Conformal prediction** for uncertainty bounds
3. **Federated learning** across motor fleet
4. **AutoML** for hyperparameter optimization
5. **Explainable AI** (SHAP values) for anomaly root cause
